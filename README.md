# xDR — expected decision regret

**Players give away measurable value by choosing a worse action than one available to them. This measures how much, and then tests whether the measurement survives being moved to a competition the model never saw.**

> **Status: M1-M5, M7, M8 live end to end; M6 (DeepSets encoder) deferred.**
> Real data throughout: ingest, SPADL conversion, action features, VAEP-style
> labels, a LightGBM baseline, isotonic calibration, a k-NN support gate, and
> counterfactual option enumeration (passes to visible teammates, carries,
> shots) all run against UEFA Euro 2024 and, for the transfer study, UEFA
> Women's Euro 2025. The FastAPI backend and Next.js dashboard render all of
> it live, including the option fan and regret. See
> [docs/DECISIONS.md](docs/DECISIONS.md) for the full reasoning trail and
> what's still deferred.

## Transfer study (Euro 2024 → Women's Euro 2025)

Trained once on Euro 2024; evaluated on Women's Euro 2025 (31 matches,
60,411 actions, 84.6% frame coverage) — a competition the model never saw,
before and after recalibrating on a held-out 20% of the target.

| | Source (in-comp.) | Target, before | Target, after |
|---|---|---|---|
| `label_scores` ECE | 0.00235 | 0.00754 | 0.00516 |
| `label_scores` Brier | 0.00611 | 0.01397 | 0.01478 |
| `label_concedes` ECE | 0.00199 | 0.00281 | 0.00112 |
| `label_concedes` Brier | 0.00195 | 0.00317 | 0.00304 |

`label_scores` ECE degrades 3.21x on transfer (SPEC's plausible range is
1.5-5x — this lands inside it) and recalibration recovers 45.8% of the gap.
`label_concedes` degrades a smaller 1.41x and recalibration recovers all of
it and then some (206.9% — the recalibrated target ECE ends up *below* the
source's own in-competition figure). Regenerated by `make transfer` from
`artifacts/transfer.json`.

## Support gate

k=20 nearest neighbours in standardized numeric action-feature space (155
columns), fit on train, percentile-ranked against validation-set
self-distances (SPEC.md §9). Verified on synthetic OOD points
(`test_support.py`): a point far outside the training cluster in every
dimension scores support=0.0, correctly below the 0.35 floor. On real
counterfactual candidates (below), 51.0% are gated — just above SPEC's
15-50% target band, not tuned further this pass. On real historical
(in-distribution) test-split actions, 36.06% are gated, matching the
~35% (`min_support`) the percentile-rank construction predicts for
same-distribution data by itself — a sanity check, not the acceptance
target.

Frame-embedding half of SPEC's reference space (§9.2) is not included; the
gate runs on the deterministic action-feature branch alone, since the
DeepSets encoder (M6) is still deferred.

## Counterfactual layer

For the ~5,100 moments the dashboard actually serves (pass/dribble/shot
actions, top 100 per match by value, across all 51 Euro 2024 matches): a
pass to each *visible* teammate from the 360 freeze frame, a carry to each
cell of a coarse 8-direction/2-distance grid, and a shot — 114,971 candidates
enumerated, 51.0% gated below the support floor.

| | |
|---|---|
| Moments with a real (non-null) regret | 2,794 / 5,100 (54.8%) |
| Mean regret, scored moments | 0.0341 |
| Mean regret 95% CI (match-level bootstrap, 2,000 draws) | [0.0271, 0.0419] |
| Median regret | 0.0221 |
| Fraction exactly zero (player's choice already optimal among scored options) | 39.9% |
| Max regret observed | 0.969 |

**This is an upper bound, not a point estimate.** SPEC.md §10's outcome-
handling decision defaults to *assuming every candidate succeeds* rather than
training a completion-probability model to marginalize over (the explicitly
sanctioned v1 default). A declined 40-metre pass is scored as if it always
arrives. Regret computed from it is the most a player could plausibly have
gained, not what they were expected to gain.

Regret is withheld (`null`, rendered as "gap unsupported") whenever the
action actually taken is itself unsupported, or every enumerated alternative
was gated — not defaulted to zero. The remaining ~104,885 ingested actions
outside the served top-100-per-match subset keep the same honest `null`, for
runtime reasons documented in `docs/DECISIONS.md`, not because they were
found to be unscoreable.

## What this is

Every on-ball action has alternatives the player declined. xDR enumerates those
alternatives from the StatsBomb 360 freeze frame, scores each with the same
possession-value model that scores the action taken, and reports the gap.

The counterfactual layer is the interesting half, and it's live. The
**defensible** half underneath it is the calibration work: a model that ranks
actions correctly can still report a value magnitude that means nothing, and
this pipeline measures whether that magnitude is trustworthy — in-competition
and under transfer — before anything is built on top of it.

Two guards keep the counterfactual layer honest:

- Every option carries a support score. Options below the floor come back
  **unscored** rather than given a number — rendered as dashed outlines in
  the pitch view, never hidden.
- Regret is withheld entirely when either side of the subtraction is
  unsupported, rendered as "gap unsupported," never `0.0000`.

## Reproducing

```bash
make install
make ingest      # real StatsBomb data -> data/raw, data/parquet (Euro 2024 + Women's Euro 2025)
make features    # SPADL actions -> VAEP-style action features + labels
make train       # LightGBM baseline, match-level 60/15/10/15 split
make calibrate   # isotonic calibration on the held-out calibration split
make report      # Brier decomposition, ECE, match-level bootstrap CI
make transfer    # cross-competition transfer study, before/after recalibration
make support     # k-NN support gate index
make serve-db    # counterfactual enumeration + scoring -> artifacts/xdr.duckdb
```

`make reproduce` chains `transfer` and `serve-db` (which pull in everything
before them). Seeds are fixed in `configs/base.yaml`. Run artifacts land in
`runs/{run_id}/` with the config hash that produced them; the same files are
mirrored into `artifacts/` for serving.

```bash
make serve   # FastAPI on :8000
make web     # Next.js on :3000, proxying /api to the above
make test    # pytest -- see docs/DECISIONS.md for current coverage
```

`make` itself was not available on the machine this pass was built on; the
targets above were run as their underlying commands directly and are correct,
but `make reproduce` as a literal invocation has not been exercised.

## Method (what's built)

**Data.** StatsBomb open data, via `socceraction.data.statsbomb.StatsBombLoader`
(not `statsbombpy` directly — see docs/DECISIONS.md for why), restricted to
competitions with confirmed 360 coverage (`match_available_360`, not the
similarly-named but unrelated `match_updated_360`). Verified live: UEFA Euro
2024 (51 matches, 109,985 actions, 86.8% frame coverage) and UEFA Women's
Euro 2025 (31 matches, 60,411 actions, 84.6% frame coverage).

**Coordinates.** Raw StatsBomb grid cells → SPADL metres happens once, in
`xdr/data/spadl.py`, including the half-cell offset correction StatsBomb's
grid-based coordinates require (a plain linear scale is off by ~0.4m
everywhere — plausible-looking, wrong). Attacking direction is normalized
home/away, verified against real per-period shot locations rather than
assumed.

**Features and labels.** Deterministic action features via `socceraction`'s
standard VAEP feature set (23 action types × 3-action window). VAEP-style
`scores`/`concedes` labels over a 10-action horizon, computed **per match**
— calling the underlying `socceraction` label functions on a multi-match
concatenation directly would let horizon lookahead cross into the next
match's opening actions, and `test_labels.py` asserts this doesn't happen.
Positive rate on Euro 2024: 0.86% (SPEC target: 0.5-3%).

**Model.** LightGBM, action-features-only. This is the number a future
DeepSets frame encoder will need to beat. Isotonic calibration fit on a
held-out 10% calibration split, disjoint from train/validation/test.

**Transfer.** Same trained model and source calibrator, applied to Women's
Euro 2025; a new calibrator fit on a held-out 20% of the target, disjoint
from the evaluation slice (`test_transfer.py` asserts this).

**Support gate.** k-NN distance in standardized action-feature space,
percentile-ranked against validation self-distances. Gates counterfactual
candidates below `min_support` (default 0.35).

**Counterfactuals.** Feature rows for hypothetical actions are built by
reusing the exact same `socceraction` feature functions and gamestates
structure the real training features go through — not reimplemented by hand
— with only the candidate action's own attributes swapped in.

**Not built (see docs/DECISIONS.md for scope and follow-up path):**
freeze-frame DeepSets encoder (M6) and its ablation against the LightGBM
baseline; a completion-probability model to replace the assume-success
upper bound.

**Deployment.** `api/Dockerfile` builds the API image from the repo root
(it bakes `configs/` and `artifacts/` alongside the package), and
`.github/workflows/ci.yml` runs ruff, pytest, the web typecheck, and the
Next.js build on every push. Neither the image build nor a hosted deploy
has been exercised yet — no container runtime was available on the machine
this pass was built on, and no container host has been chosen (SPEC.md §14
leaves it open, with Railway as the config-file assumption).

## Limitations

- Regret is an **upper bound**, not a point estimate — see "Counterfactual
  layer" above. This is the largest open quality decision in the project
  (SPEC.md §18 item 2), taken deliberately per SPEC's own sanctioned v1
  default rather than silently.
- The counterfactual layer runs on ~5,100 of 109,985 ingested actions (the
  ones the dashboard serves), not the full corpus — a runtime scope cut, not
  a claim that the rest are unscoreable.
- Off-distribution extrapolation is real for scored candidates too; the
  support gate bounds it, it does not eliminate it.
- 360 coverage is partial and camera-dependent. Frames with few visible
  players produce smaller option sets and therefore smaller measured regret
  — a bias toward zero, not away from it.
- Nothing here accounts for fatigue, instruction, or scoreline intent. A
  "suboptimal" pass may be exactly what the coach asked for.
