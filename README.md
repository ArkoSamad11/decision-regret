# xDR — expected decision regret

**Players give away measurable value by choosing a worse action than one available to them. This measures how much, and then tests whether the measurement survives being moved to a competition the model never saw.**

> **Status: first live pass, not the full study.** This pass ships a real,
> end-to-end pipeline against real data — ingest, SPADL conversion, action
> features, VAEP-style labels, a LightGBM baseline, isotonic calibration, a
> FastAPI backend, and a Next.js dashboard, all verified live against UEFA
> Euro 2024. The counterfactual layer (declined alternatives, regret, the
> option fan), the DeepSets frame encoder, the support gate, and the
> cross-tournament transfer study are **not built yet** — see
> [docs/DECISIONS.md](docs/DECISIONS.md) for the exact scope cut and why.
> Numbers below are real, from the in-competition pass only.

## What this is

Every on-ball action has alternatives the player declined. xDR enumerates those
alternatives from the StatsBomb 360 freeze frame, scores each with the same
possession-value model that scores the action taken, and reports the gap.

The counterfactual layer is the interesting half; it is the part not yet
built. The **defensible** half — and what this pass actually delivers — is
the calibration work underneath it: a model that ranks actions correctly can
still report a value magnitude that means nothing, and this pipeline measures
whether that magnitude is trustworthy before anything gets built on top of it.

Two guards will keep the eventual counterfactual layer honest (designed now,
enforced once M7/M8 land):

- Every option will carry a support score. Options below the floor come back
  **unscored** rather than given a number.
- Regret is withheld entirely when either side of the subtraction is
  unsupported.

The API and dashboard already speak this contract: every scored moment has
`best`, `regret`, and `options` fields, genuinely `null`/`[]` right now (not
omitted, not defaulted to zero) rather than added later as a breaking change.
The dashboard renders "gap unsupported" for a null regret, never `0.0000`.

## Reproducing

```bash
make install
make ingest      # real StatsBomb Euro 2024 data -> data/raw, data/parquet
make features    # SPADL actions -> VAEP-style action features + labels
make train       # LightGBM baseline, match-level 60/15/10/15 split
make calibrate   # isotonic calibration on the held-out calibration split
make report      # Brier decomposition, ECE, match-level bootstrap CI
make serve-db    # writes artifacts/xdr.duckdb for the API to read
```

`make reproduce` chains `report` and `serve-db` (which pull in everything
before them). Seeds are fixed in `configs/base.yaml`. Run artifacts land in
`runs/{run_id}/` with the config hash that produced them; the same files are
mirrored into `artifacts/` for serving.

```bash
make serve   # FastAPI on :8000
make web     # Next.js on :3000, proxying /api to the above
make test    # pytest, ~59% coverage on api/src/xdr/ -- see docs/DECISIONS.md
```

`make` itself was not available on the machine this pass was built on; the
targets above were run as their underlying commands directly and are correct,
but `make reproduce` as a literal invocation has not been exercised.

## Method (what's built)

**Data.** StatsBomb open data, via `socceraction.data.statsbomb.StatsBombLoader`
(not `statsbombpy` directly — see docs/DECISIONS.md for why), restricted to
competitions with confirmed 360 coverage (`match_available_360`, not the
similarly-named but unrelated `match_updated_360`). Verified live: UEFA Euro
2024, 51 matches, 109,985 actions, 86.8% carrying a freeze frame.

**Coordinates.** Raw StatsBomb grid cells → SPADL metres happens once, in
`xdr/data/spadl.py`, including the half-cell offset correction StatsBomb's
grid-based coordinates require (a plain linear scale is off by ~0.4m
everywhere — plausible-looking, wrong). Attacking direction is normalized
home/away, verified against real per-period shot locations rather than
assumed.

**Features and labels.** Deterministic action features via `socceraction`'s
standard VAEP feature set (23 action types × 3-action window). VAEP-style
`scores`/`concedes` labels over a 10-action horizon, computed **per match**
— calling the underlying `socceraction` label functions on a multi-match
concatenation directly would let horizon lookahead cross into the next
match's opening actions, and `test_labels.py` asserts this doesn't happen.
Positive rate on Euro 2024: 0.86% (SPEC target: 0.5-3%).

**Model.** LightGBM, action-features-only. This is the number a future
DeepSets frame encoder will need to beat. Isotonic calibration fit on a
held-out 10% calibration split, disjoint from train/validation/test.

**Not built (see docs/DECISIONS.md for scope and follow-up path):**
freeze-frame DeepSets encoder, k-NN support gate, counterfactual option
enumeration, cross-tournament transfer study, Docker/CI/Vercel deployment.

## Limitations

- This pass reports in-competition calibration only. Whether it survives
  transfer to a competition the model never saw — the actual thesis — is not
  yet tested.
- Scoring unselected actions (once the counterfactual layer exists) will be
  off-distribution extrapolation. Support scores will bound it; they will not
  eliminate it.
- 360 coverage is partial and camera-dependent. Frames with few visible
  players will produce smaller option sets and therefore smaller measured
  regret once that layer exists — a bias toward zero, not away from it.
- Nothing here accounts for fatigue, instruction, or scoreline intent. A
  "suboptimal" pass may be exactly what the coach asked for.
